# Playbook: สิทธิ์เครื่อง / GPS / การติดตั้ง — แยกตามเคส

> อัปเดต 2026-11-12 · ใช้คู่กับโค้ดใน
> `src/app/config/device-help.ts` (ข้อความที่โชว์ผู้ใช้) และ
> `src/app/services/device-check.service.ts` (การตรวจจับ)
> ถ้าแก้เคสใด ให้แก้ทั้งสองที่ให้ตรงกัน

---

## 1. หลักคิด

1. **เว็บเปิดการตั้งค่าเครื่องให้ไม่ได้** (ทั้ง iOS และ Android ไม่มีลิงก์ไปหน้า Settings จากเว็บ)
   สิ่งที่ทำได้คือ **บอกให้ตรงเคส + บอกทางกดทีละขั้นตามรุ่นเครื่อง** — นั่นคือสิ่งที่ help sheet ทำ
2. **ถามสิทธิ์ตอนผู้ใช้กดปุ่มเท่านั้น** และ**อธิบายก่อนถาม** (primer) — iOS จำการกด "ไม่อนุญาต"
   ไว้ถาวร แก้ได้ทางเดียวคือไปที่การตั้งค่า ถามครั้งแรกต้องได้ "อนุญาต"
3. **ถ้ารู้อยู่แล้วว่าถามไปไม่มีผล ไม่ต้องถาม** — เช่น Android บอกว่า `denied` แล้ว →
   ข้าม prompt ไปโชว์วิธีแก้เลย
4. **บางอย่างเว็บรู้ไม่ได้** (เช่น iOS ไม่บอกว่าปิด Location Services ทั้งเครื่อง หรือเปิดโหมดพลังงานต่ำ)
   → อย่าเดา ให้ข้อความครอบคลุมทุกจุดที่สวิตช์อาจถูกปิด เรียงจากสาเหตุที่พบบ่อยก่อน

## 2. ตารางเคส

| # | เคส (`HelpIssueId`) | ตรวจจับอย่างไร | สาเหตุจริง | ผู้ใช้เห็นอะไร |
|---|---|---|---|---|
| 1 | `in-app-browser` | UA มี `Line/`, `FBAN/FBAV`, `Instagram`, `Messenger`, `TikTok`, Android `; wv)` | สแกน QR ด้วย LINE / เปิดลิงก์จากแชต | **LINE: เด้งออกไป Safari/Chrome อัตโนมัติ** (`?openExternalBrowser=1` ใน `index.html`) · อื่น ๆ: popup + ปุ่ม "เปิดในเบราว์เซอร์" (Android = `intent://` เข้า Chrome, iOS 17+ = `x-safari-https://`) + ปุ่มคัดลอกลิงก์ |
| 2 | (ก่อนบูต) iOS < 15 | `index.html` อ่าน `OS 14_` จาก UA ด้วย ES5 | Angular 22 ไม่รองรับ iOS 12–14 → หน้าขาว | กล่องข้อความ "กรุณาอัปเดต iOS / ยืมเครื่องเจ้าหน้าที่" แทนหน้าขาว |
| 3 | `insecure-context` | `!window.isSecureContext` | เปิดผ่าน http หรือ IP | popup "แจ้งเจ้าหน้าที่ — ลิงก์ตั้งค่าผิด" (เกิดได้แค่ตอนติดตั้ง QR ผิด) |
| 4 | `geo-unsupported` | ไม่มี `navigator.geolocation` | เบราว์เซอร์แปลก/เก่า | ให้เปิดใน Safari / Chrome |
| 5 | `geo-denied` | error code `1` หรือ `permissions.query` = `denied` | ปิด Location Services ทั้งเครื่อง / ปิด "เว็บไซต์ Safari" / เคยกด "ไม่อนุญาต" | ขั้นตอนครบทั้ง 3 จุด (iOS) หรือ 3 จุด (Android) + ปุ่ม "ลองอีกครั้ง" |
| 6 | `geo-unavailable` | error code `2` | อนุญาตแล้วแต่ GPS ไม่มีสัญญาณ / โหมดเครื่องบิน | ไปที่โล่ง, ปิดโหมดเครื่องบิน/ประหยัดพลังงาน, เปิด Wi-Fi ไว้ |
| 7 | `geo-timeout` | error code `3` **2 ครั้งติด** (ครั้งเดียวในป่าเป็นเรื่องปกติ) | สัญญาณอ่อนใต้เรือนยอด | แจ้งครั้งเดียวต่อ session ไม่กวนซ้ำ |
| 8 | `geo-approximate` | `accuracy ≥ 1500 m` **3 fix ติด** | ปิด "ตำแหน่งที่แม่นยำ" (iOS 14+ / Android 12+) | วิธีเปิด Precise Location — ถ้าไม่แก้ ภารกิจจะไม่เด้งเลย |
| 9 | `tracking-paused` | หน้าถูกซ่อน > 20 วินาทีระหว่างเดิน | จอดับ / สลับแอป → มือถือหยุดส่ง GPS ให้เว็บ | แจ้งครั้งเดียว + วิธีตั้ง Auto-Lock · **ป้องกันด้วย Screen Wake Lock** (iOS 16.4+, Android Chrome) |
| 10 | `storage-blocked` | เขียน `localStorage` แล้ว throw (ไม่ใช่ quota) | โหมดส่วนตัว / ปิดคุกกี้ | ให้เปิดแท็บปกติ / เปิดคุกกี้ — **เตือนตั้งแต่เปิดแอป** ก่อนเดินจริง |
| 11 | `storage-full` | `QuotaExceededError` | รูปภารกิจ base64 + เส้นทาง เกิน ~5 MB | เตือนว่าข้อมูลล่าสุดอาจไม่ถูกบันทึก (เดิม **เงียบ**) |
| 12 | `storage-eviction` | iOS + `storage.persist()` ไม่ได้ | Safari ลบข้อมูลเว็บที่ไม่ได้เปิด 7 วัน | แนะนำเดินจบในวันเดียว · แอปขอ `persist()` ให้ตอนกดเริ่ม |
| 13 | `offline` | event `offline` | ไม่มีสัญญาณ | เดินต่อได้ แต่แผนที่พื้นหลัง/ล็อกอิน/อีเมลต้องรอเน็ต |
| 14 | `camera-denied` | ตรวจจาก `<input capture>` ไม่ได้ | ปิดกล้องให้ Safari/Chrome | อยู่ใน catalog สำหรับเจ้าหน้าที่/หน้าตรวจ — ผู้ใช้ยังเลือก "คลังรูปภาพ" แทนได้ |
| 15 | `notifications-ios` | iOS ไม่มี `Notification` ใน Safari | Apple จำกัด push เฉพาะแอปบนหน้าจอโฮม 16.4+ | อธิบายว่าจะแจ้งเตือนในหน้าแอปแทน |
| 16 | `ios-standalone-storage` | iOS + เปิดจากหน้าจอโฮม | แอปบนหน้าจอโฮมเก็บข้อมูล**แยก**จาก Safari | เตือนครั้งเดียว: ใช้ที่ใดที่หนึ่งตลอดเส้นทาง |

ข้อสังเกต:

- **iOS แยกไม่ได้ว่า "ปิดทั้งเครื่อง" หรือ "ปิดแค่เว็บนี้"** — error code เป็น `1` เหมือนกัน และ Safari ไม่มี
  Permissions API ที่เชื่อถือได้ จึงรวมเป็นเคส 5 เคสเดียว โดยเรียงขั้นตอนตามลำดับที่ต้องเปิด
- **iOS ไม่มี `navigator.vibrate`** — โค้ดแผนที่สั่นเครื่องได้เฉพาะ Android บน iPhone ต้องพึ่ง popup + เสียง
  (และเสียงจะดังได้ต่อเมื่อผู้ใช้เคยแตะหน้าจอมาแล้ว)
- **โหมดพลังงานต่ำ** ตรวจจากเว็บไม่ได้ แต่มีผล: Safari จะปฏิเสธ wake lock และลดความถี่ GPS
  → อยู่ในขั้นตอนของเคส 6

## 3. ลำดับที่ผู้ใช้เจอ (flow)

```
สแกน QR
 ├─ ด้วย LINE ─────────► index.html เติม ?openExternalBrowser=1 → เปิด Safari/Chrome เอง
 ├─ iOS 12–14 ─────────► กล่อง "กรุณาอัปเดต iOS" (แทนหน้าขาว)
 └─ เบราว์เซอร์ปกติ
     ├─ 1.2 วิ ─► in-app อื่น ๆ? → popup #1 · เขียน storage ไม่ได้? → popup #10
     └─ หน้า Home (ไม่มี login / เลือกภาษา / แบนเนอร์ consent / tutorial — ข้อความ 3 ข้อแสดงบนหน้าเลย)
         ├─ กด "เริ่มต้น" (= ยินยอมเก็บข้อมูล + ใช้ตำแหน่ง) ──► prompt ของ OS "อนุญาต" ──► แผนที่
         ├─ Android บอก denied → popup #5 ทันที (ไม่ถามซ้ำให้เสียเวลา)
         └─ ระหว่างเดิน
             ├─ error 1/2/3, accuracy หยาบ → popup #5 / #6 / #7 / #8
             ├─ จอดับ > 20 วิ → popup #9 (ครั้งเดียว)
             └─ storage เต็ม → popup #11
```

## 4. หน้า `/check` — ตรวจความพร้อมเครื่อง

- เปิดได้โดยไม่ต้องล็อกอิน · มีลิงก์จากหน้า Home ใต้ปุ่มเริ่ม และจากท้ายทุก popup
- ตรวจ: เบราว์เซอร์/in-app, https, รองรับ GPS, **ทดสอบ GPS จริง** (แสดงความแม่นยำ ±m),
  บันทึกข้อมูลได้, `persist()`, wake lock, อินเทอร์เน็ต, การแจ้งเตือน
- แต่ละแถวที่ไม่ผ่านมีปุ่ม "วิธีแก้" เปิด popup ของเคสนั้น
- ท้ายหน้ามี **"รหัสสำหรับแจ้งเจ้าหน้าที่"** เช่น `ios17/safari · browser:o,location:f,...`
  → เจ้าหน้าที่อ่านแล้วรู้ทันทีว่าติดตรงไหน (`o`=ok `w`=warn `f`=fail `u`=unknown)

**แนะนำหน้างาน:** ป้ายที่ทางเข้าใส่ QR สองอัน — "เริ่มเดิน" (`/s/<site>`) และ
"ตรวจเครื่องก่อน" (`/check`) หรือให้เจ้าหน้าที่เปิด `/check` บนเครื่องผู้มาเยือน

## 5. Add to Home Screen — ทำให้ง่ายที่สุดได้แค่ไหน

| | Android (Chrome/Samsung/Edge) | iPhone / iPad |
|---|---|---|
| ติดตั้งให้อัตโนมัติจากการสแกน | ❌ ไม่มีเบราว์เซอร์ไหนยอม | ❌ |
| ติดตั้งแตะเดียว | ✅ ปุ่ม "ติดตั้งแอป" (`beforeinstallprompt`) — อยู่ในหน้า `/check` และ popup | ❌ Apple ไม่มี API นี้ |
| ต้องทำเอง | — | แชร์ ⤴ › เพิ่มไปยังหน้าจอโฮม › เพิ่ม (~10 วินาที) — มีคู่มือทีละขั้นใน popup |
| ข้อมูลกับเบราว์เซอร์ | ใช้ร่วมกัน | **แยกกัน** — เริ่มที่ไหนต้องจบที่นั่น |
| Push notification | ✅ | ✅ เฉพาะแอปบนหน้าจอโฮม iOS 16.4+ |

**ข้อแนะนำ:** สำหรับเส้นทางอาบป่า **ไม่ควรบังคับติดตั้ง** — ใช้ใน Safari/Chrome ได้ครบทุกอย่าง
การบังคับติดตั้งบน iPhone เพิ่มขั้นตอน และถ้าผู้ใช้เริ่มเดินใน Safari แล้วค่อยติดตั้ง ความคืบหน้าจะหาย
จึงวางการติดตั้งเป็น "ไม่บังคับ" ในหน้า `/check` เท่านั้น

ถ้าวันหนึ่งต้องการ "สแกนแล้วได้แอปเลย" จริง ๆ บน iPhone ทางเดียวคือ **App Clip** (ต้องเป็นแอป native
ใน App Store + บัญชี Apple Developer) — เป็นโปรเจ็คแยก ไม่ใช่งานเว็บ

## 6. Push Notification (HANDOVER ข้อ 9) — สถานะ

**ยังไม่ได้ทำ — ติดที่คีย์** ซึ่งต้องสมัครด้วยบัญชีของเจ้าของโปรเจ็คเอง (ผู้ช่วยสมัครแทนไม่ได้):
Firebase project → `firebaseConfig` 6 ค่า, VAPID key, Service Account JSON (ฝั่ง API)

ก่อนลงทุน ให้ตอบคำถามนี้ก่อน: **ต้องการแจ้งเตือนตอนผู้ใช้ไม่ได้เปิดแอปหรือไม่?**

- ระหว่างเดิน ผู้ใช้เปิดแผนที่อยู่แล้ว → popup + เสียงในแอป (มีอยู่แล้ว) พอ และใช้ได้ทุกเครื่อง
- บน iPhone push ใช้ได้เฉพาะเมื่อ **ติดตั้งลงหน้าจอโฮม** → ขัดกับข้อแนะนำข้อ 5
- push คุ้มเมื่อจะส่งหลังจบเส้นทาง เช่น "เกียรติบัตรพร้อมแล้ว" / "ทำแบบประเมินหลังเดิน 7 วัน"
  — ซึ่งอีเมล (มีอยู่แล้ว) ทำได้เหมือนกันโดยไม่ต้องติดตั้ง

เมื่อได้คีย์แล้ว ขั้นตอนอยู่ใน HANDOVER ข้อ 9 "เมื่อจะเริ่มทำจริง"

## 7. ทดสอบด้วยตัวเองอย่างไร

| เคส | วิธีจำลอง |
|---|---|
| denied | iPhone: การตั้งค่า › Safari › ตำแหน่ง → ปฏิเสธ · Chrome: 🔒 › ตำแหน่ง › บล็อก |
| approximate | iPhone: บริการหาตำแหน่ง › เว็บไซต์ Safari › ปิด "ตำแหน่งที่แม่นยำ" |
| in-app | ส่งลิงก์ให้ตัวเองใน LINE / Messenger แล้วกดเปิด |
| storage-blocked | Safari แท็บส่วนตัว (iOS เก่า) / ปิดคุกกี้ทั้งหมด |
| tracking-paused | กดเริ่ม → ล็อกจอ 30 วินาที → ปลดล็อก |
| iOS < 15 | Chrome DevTools › Network conditions › UA = iPhone iOS 14 |
| ดูหน้าตา popup ทุกเคส | เปิด `/check` แล้วกดปุ่ม "วิธีแก้" ของแต่ละแถว |
